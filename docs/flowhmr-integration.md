# FlowHMR 接入

## 使用流程

视频反推的识别方式增加 FlowHMR。简易识别仍为默认，已经安装的 Human3R 保留。

1. 设置中选择 FlowHMR，阅读许可并下载。
2. 点击“官网下载”，从 MANO / SMPL 官方页面取得 **Extended SMPL+H** 的 `smplh.tar.xz`。
3. 点击“导入人体文件”，选择该压缩包或其中的 `neutral/model.npz`。
4. 选择视频区间、原视频镜头类型和目标人物，开始转换。
5. 打开生成的工程，继续修改走位、动作片段和人物外形。

运行环境、模型和人体文件分别显示安装状态。清理缓存不删除模型，卸载只处理所选识别方式，保留转换结果。

## 来源与许可

- [FlowHMR](https://github.com/flowhmr/flowhmr)：算法来源，源代码 Apache-2.0；模型权重另有非商业许可。
- [FlowHMR-Windows](https://github.com/xiaoerofficial021-collab/FlowHMR-Windows)：采用其本地部署、显存分阶段管理和多人站位代码，固定提交 `c3efad9d9028d6ab031a150a70476853e4ba3f41`。
- [模型许可](../desktop/video-reconstruction/FlowHMR-LICENSE.txt)：随软件提供全文，用户在下载前确认。
- [Extended SMPL+H](https://mano.is.tue.mpg.de/download.php)：用户在官方页面按对应条款下载，软件不代登录或代同意，也不重新分发人体文件。
- YOLOX、SAM 3D Body、VGGT-Ω、DINOv3 使用各自上游代码及许可。源码下载保留原许可与 THIRD_PARTY_NOTICES；各组件版本和校验值见 `flow-manifest.cjs`。

RGBMocap 的原生接触修正本次未启用，不能将其效果计入当前实现。

姿态提取复用上游显存自适应批量（`sam_chunk_size=None`），按当前空闲显存与可复用显存规划每批帧数；显存不足时复用上游的缩小批量重试。没有降低采样帧率、输入分辨率或生成步数。桌面与 MCP 共用该 worker，无需分别配置。

## 开发契约

`flow-runtime.cjs` 管理独立的 `flowhmr/models`、`flowhmr/runtime`、`flowhmr/cache`。进程使用原有隐藏窗口、取消进程树和日志流程。所有 Python、包缓存及模型都在所选目录；不修改系统 PATH 或安装全局 Python。

源码固定校验值，下载后仅修改模型目录和 DINOv3 代码加载路径，使其使用本地受管目录。源码包中的文档符号链接跳过，不在用户机器上创建外部链接。依赖使用 PyPI 和官方 PyTorch CUDA 12.8 源。

`flow-worker.py` 调用上游识别，保留 `flow-raw-*.npz` 原始导出。多人对齐属于程序后处理，单独记录在 `flow-motion.json.placement`。未添加手工关键帧、按视频调参或人工修正识别结果。临时视频、特征张量和重复素材位于任务的 `flow-work`；工程成功嵌入后删除，失败时可通过清理缓存删除。

输出使用 30 fps，单次最多 5000 帧。52 关节的局部旋转和体型参考骨架作为 glTF 动作资源嵌入工程；XZ 位移写入对象路径，垂直动作保留在骨架根节点。22 个身体关节映射到现有适配器，不开发第二套动作系统。可见时段按识别轨迹保留。摄影机复用 VGGT／静态相机内外参及 SAM 人体观测，采用与人物对齐相同的旋转、尺度和平移，输出位置、视线、焦距、倾斜和画面偏移关键帧。不是绑定人物的跟拍。旧结果没有 camera 时继续使用原固定机位兼容，不将旧数据伪装为已还原。

`director_reconstruct` 共用上述流程：`configure(engine:"flowhmr")`、`download`、`import-body(path)`、`start(cameraMode,actorModel)`、`state`、`cancel`、`result`。人体文件导入采用异步任务，可取消；同一 requestId 不重复执行。许可仍由用户在界面确认。
