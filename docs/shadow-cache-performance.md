# 通用阴影复用

`src/lighting/shadow-cache.ts` 在布景和摄影机视口分别记录阴影输入。模型的世界变换、可见性、骨架、形变权重、几何版本、透明贴图及投影灯变化时重新绘制；只旋转取景相机或重复采样相同姿态时复用现有阴影。不是按文件名、资产来源或 Blender 专门启用的规则。

- 静止及运镜时复用精确阴影，不修改工程、模型精度或灯光参数。
- 开启现有“流畅预览”时，复杂场景在拖动过程中暂时保留一个主投影，其他灯光继续照明。通过阴影强度 uniform 和更新开关简化预览，不在鼠标按下时触发全场材质重新编译。松手或取消后重绘全部阴影；关闭流畅预览则保留完整实时投影。按投影面数与投影网格数判断开销，不针对某个文件、模型或导入格式。
- 重建场景、WebGL 上下文恢复和绘制失败清除记录。
- 正式导出、深度输出、插件渲染以及媒体／抽象效果使用原绘制流程。这些路径可直接改变材质或增加渲染过程，不以基础模型状态推断其未变化。
- 会产生新阴影的动作仍需要重绘；此优化不将动态场景的帧率承诺为固定值。

## 验证

`tests/shadow-cache.test.ts` 覆盖视角、层、位置、灯光目标、可见性、几何、骨架、形变权重、透明贴图以及不同渲染器的失效规则。

`node scripts/verify-shadow-cache.mjs` 使用程序生成的多物体、多灯光场景，逐像素比较复用与强制重绘，覆盖运镜、路径动画、隐藏、移灯、阴影开关、人物动作、逆向跳帧和输出。结果集中在 `tmp/shadow-cache`。

`node scripts/verify-transform-drag.mjs` 检查高频输入每帧只提交最后一个绝对变换、松手前最后输入、取消、撤销、保存重开、松手后的完整画面及关闭流畅预览。输出集中在 `tmp/transform-drag`。`src/editor/transform-queue.ts` 只合并鼠标输入，保留原变换事务与吸附、路径、结构联动规则；松手提交前刷新待处理输入，取消则丢弃。

2026-11-12 本机 Classroom 渲染采样：273 对象、约 60 万三角面、7 点光源、2 面光源、1 太阳光。复用自动转换的原始输出，仅测渲染，不计导入耗时。双视口重复采样／运镜的稳定帧从约 125 ms 降至 24 ms，绘制调用由约 1.8 万降至约 1,500；保持全部灯光和阴影。静态、运镜、移动、隐藏四种情况与强制重绘的图像一致。结果是本机有限采样，不能外推为所有工程的性能。

同工程连续移动对象的 16 步采样，原流程约 120 ms/帧，拖动简化投影后稳定帧约 18 ms，首步约 42 ms。它与上面的精确阴影复用不同：拖动中会简化次要投影，松手后恢复；本机回归验证恢复后的图像一致。

以下完整贴图数据来自此前采用材质烘焙与 WebP 转码的实验版本，该转换方案已取消，不能作为当前导入流程的数据。材质转换后的 Classroom 包含 897 个网格、约 61 万三角面。图片共享将独立图像 Source 从 1,202 降到 310；这不是显存测量。当时无损 WebP 将转换资源从 496.7 MB 降到 263.8 MB，贴图分辨率不变。

纹理密集场景启用流畅预览后，后台预编译交互材质。拖动时保留颜色、贴图、凹凸与透明度，暂用漫反射着色并冻结阴影；松手恢复完整材质并更新阴影。正式输出、深度图和自定义渲染不使用此路径。首次交互直接使用低分辨率预览，不先等待两帧卡顿。2026-11-12 最终 16 步双视口同步 GPU 采样：稳定帧约 24–36 ms，首步约 80 ms（包括此前完整预览尚未完成的 GPU 工作），尚不能声称稳定 60 fps 或完全消除首步延迟。

`node scripts/verify-interaction-materials.mjs` 使用 420 个带贴图对象，验证首帧进入简化预览、材质引用恢复、松手后与强制重绘逐像素一致、关闭流畅预览恢复，以及截图导出不会使用交互材质。真实 Classroom 桌面验收打开约 352 MB 工程，另存后重新打开并导出截图，保留 273 个对象及 262 份资源。性能测试结束时取消变换，测试工程保留原始对象位置；材质图集来自程序转换，灯光元数据由更新后的程序重新读取源工程，无人工调色。

工程保存由 `src/files/json-blob.ts` 分块编码为原有 JSON 格式，桌面 UI 与 MCP 共用分块写入及原子提交；文件选择仍沿用原生保存窗口。写入失败不标记已保存，不覆盖旧文件。旧工程身份计算保留原 SHA-256 输入，只避免构造整份 UTF-16 JSON 字符串。

## 当前 Blender 转换耗时

2026-11-12 按轻量预演定位调整：不再烘焙复杂程序材质；保留基础颜色、已有图片与常量乘色，复用 PNG/JPEG 编码；静态对象不逐帧采样动画，动画父级、约束目标、驱动及动态修改器仍计入动画依赖。

同一 Classroom 的自动转换、编辑器加载全流程实测 108.9 秒，保留 273 个对象与 262 份模型资源。随后通过真实 UI 保存、工程内容检查和截图；没有人工修改转换结果或调色。测试输出集中于 `tmp/blender-import`，完整验收日志为 `fast-end-to-end-final2.log`。这是本机单次完整导入结果，不是所有工程的时间承诺。独立材质测试验证原图 UV、乘色、透明材质、程序颜色近似与源文件不变；动画回归覆盖静态排除及动态依赖。

## 最新交互修正

最新导入结果暴露出透明双面材质每次绘制会递增 Three.js 材质版本。原阴影键包含通用材质版本，因此未移动场景也反复重绘阴影。现改为比较真实深度输入（含透明裁切、覆盖、位移、线框与裁切面），自定义深度／距离材质仍比较版本。

视角拖动、滚轮、阻尼尾段及键盘导航接入流畅预览；播放也使用自适应画质，但保留主灯动态阴影，不冻结整段动画的阴影。单独移动布景视角时跳过未变化的摄影机视口。停止后恢复，导出继续完整画质；这些行为不修改工程内容。

2026-11-12，最新 Classroom、1920×1080 页面、双视口、16 帧同步 GPU 采样：修正前完整预览约 190–213 ms/帧；修正后交互转视角约 15–17 ms/帧，播放约 28–31 ms/帧。进入交互的首帧仍约 114 ms（包含此前完整预览排队工作），完整材质预览约 90–105 ms/帧。这是有限采样，不是持续帧率保证。数据位于 `tmp/blender-import/interaction-before.log` 与 `interaction-final.log`。

回归包括真实视角／播放按钮操作、停止后恢复分辨率、拖动物体、撤销／取消、保存重开和输出不使用交互材质。阴影测试读取原始像素，容许少量透明混合量化误差（通道最大差 1、变化通道不超过 0.01%）；实际本次场景比较均完全相同，仅输出比较出现 2 个通道相差 1。

准备后的 Electron 桌面包另用隔离配置打开同一工程，通过真实鼠标转视角和播放按钮验证。2.5 秒播放采样共 82 帧，中位帧间隔 28.1 ms，P95 为 35.1 ms；停止后恢复原画布尺寸，没有页面异常。日志：`tmp/blender-import/interaction-desktop.log`。测试窗口已退出，未替换用户正在编辑的工程。
