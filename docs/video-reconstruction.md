# 视频反推（可选本地模型）

## 当前范围

桌面版标题栏“视频反推”（帮助菜单右侧）。Human3R-672S 恢复人物姿态、相机和场景几何，再经适配器写为已有 `.director` 工程。人物用自制近似人形骨架，不下载 SMPL 人体表面资产。转换不修改正在编辑的工程，用户完成后打开结果；当前有未保存修改时提供保存、直接打开和取消。

运行环境：Windows / Linux x64 原生启动自带管理的 Python，无需 WSL 或系统 Python。按操作系统下载固定版本 uv，在用户选择目录内安装 Python 3.12 / Torch 2.5.1 CUDA 12.4，需要 NVIDIA GPU。macOS 不提供这一模型的运行入口能力，不降级到未验证的 CPU 推理。不自动安装 WSL 或系统驱动。


### 设备配置建议（2026-11-10）

设置页在首次下载前与安装后均显示配置。最低配置为工程估计，并非 Human3R 官方最低配置或 8 GB 显卡实测结论。

| 项目 | 最低配置（估计，短片段） | 推荐配置 |
|---|---|---|
| 显卡 | NVIDIA RTX 20/30/40 系列，8 GB 显存 | 同系列，16 GB 显存 |
| 内存 | 16 GB | 32 GB |
| CPU | 4 核 8 线程 | 6 核 12 线程及以上 |
| 可用磁盘空间 | 20 GB | SSD，40 GB |

依据：本项目已有短片测试的 PyTorch 峰值分配约 3.61–3.63 GiB，预留约 3.93 GiB；8 GB 显存估计额外留出驱动、编辑器与图像处理空间。主存和磁盘随分析帧数及结果增长，因此最低配置只面向短片段，长视频与多人场景建议分段。CPU/内存/磁盘档位是本软件的配置建议，尚未逐档硬件验收。

[官方推理说明](https://github.com/fanegg/Human3R/blob/master/docs/inference.md)的速度基准使用 RTX 4090 与双 Xeon Gold 6530，并未给出最低硬件配置。软件当前使用 Torch 2.5.1 / CUDA 12.4；RTX 50 系列不列入当前建议范围。Windows/Linux x64 为运行入口支持范围，Linux 完整 GPU 验收状态见下文。不支持 CPU-only、AMD/Intel GPU 或 macOS 推理。本次仅添加说明，不增加安装拦截或硬件审批。

## 许可和下载

- 首次由用户阅读并同意 Human3R 原许可；明确非商业限制，商用需另行授权。同意不授予额外权利。
- 许可内容 SHA-256 为确认版本，记录本机用户配置目录；相同内容跨启动复用，内容变化重新确认。取消不会接受或下载。AI / MCP 不能调用接受许可动作。
- 检查点固定 Hugging Face 提交和 SHA-256，源码固定官方 GitHub 提交。模型不随安装包分发；下载从上游官方源发起。安装包只含适配脚本和 Human3R 许可副本。
- 下载写 `.part`，完成校验后替换正式文件；失败、取消移除未完成文件。重试复用已校验模型。下载失败不会留下“可用”标记。
- 上游源码中的许可随其下载保留。推理适配省略不用的查看器导入，使用 checkpoint 自带均值缓冲区和有符号 RoPE 公式；不修改权重。不能将整个第三方运行环境宣称为 MIT。

## 代码与数据

- `desktop/video-reconstruction/host.cjs` 管理用户许可、设置和异步下载/转换，`download.cjs` 管下载完整性，`runtime.cjs` 安装并启动独立环境，`storage.cjs` 管理归属和清理。
- `run-inference.py` 保留原始预测，`convert-analysis.py` 执行确定性坐标/几何转换；`src/reconstruction/build-project.ts` 复用模型校验和工程格式。
- 运行目录下 `models/` 为模型、`runtime/<os>-x64/` 为 uv、Python、虚拟环境和源码，`cache/` 为下载/安装缓存，`runs/<id>/` 为输入抽帧、原始预测、结果、日志及任务记录。没有输入视频副本。实验测试文件统一在 `tmp/video-to-project/`。
- 进程以参数数组启动、Windows 隐藏控制台；取消时 Windows 通过 taskkill /T 结束进程树，Linux 结束独立进程组。退出中断任务，下次打开显示中断，不自动重新执行。
- `director_reconstruct` 共用原生宿主：state/open/download/start/cancel/result/configure/storage/preview。任务返回后持续查询 state；result 得到路径后使用既有 director_import。转换不占用渲染器的项目写锁；打开结果仍使用事务、revision、资源准备和撤销。

## 原生运行和过程预览

- uv 仅使用管理目录内 Python，禁用注册表和 PATH 注册，不安装全局包；pip、uv、Torch、HF、CUDA、临时目录与 Python 字节码缓存均定向到所选目录。首次准备展示保存位置和空间建议。
- 旧 WSL 目录保留，原生环境使用其下 native-runtime；不把旧环境冒充为新原生环境。
- 存储目录需要为空或含本功能归属标记。安装成功清除下载缓存；转换成功清除逐帧 NPZ、源帧 JPG 和已逐字节核对嵌入工程的 GLB 副本。取消转换也清除这些中间文件，保留 `.director`、预览及日志。清理缓存同时处理历史成功、取消、失败及中断任务的中间文件；损坏的已完成工程保留输入以便恢复。移除运行环境删除 runtime/models/cache/ready.json，保留工程。不自动删除其他旧目录。
- preview.py 对原始预测做轻量抽样，输出源帧、空间点和人体关节，不回写预测。界面按需绘制、关闭释放；MCP 预览仅返回帧、时间、人物数量，避免大图挤占上下文。
- WSL 可验证 Linux 安装与计算分支，不能代表原生 Linux 桌面交互已经验收。


2026-11-06 原生改造验收：Windows 从独立目录下载并安装 uv/Python/Torch 和其他依赖，重用此前下载且再次校验的官方检查点和源码。未调用系统 Python 或 WSL 完成转换。桌面真实转换官方示例 3 秒/18 帧，得到 3 人、2 个背景物体及摄影机；过程源帧与空间骨架持续更新，MCP 状态、打开工程、未保存流程和无页面异常检查通过。第二次总用时约 65.7 秒，其中模型推理约 7.0 秒，峰值 GPU 分配约 3.61 GiB；这不是任意视频的性能保证。

## 工作区交互

视频反推使用现有三栏工作区：左侧选择源视频，中间原视频/并排/识别预览，右侧范围、精度和场景参数。转换视图暂时收起工程时间轴；返回编辑恢复原画布、选择与时间轴，不替换工程或销毁画布。转换任务可以在返回编辑后继续，重新进入恢复状态。

源视频通过选中文件的临时同源地址按 Range 流式读取，不复制或整体加载文件，也不依赖 Python。未下载模型时也能播放源视频并定位起点。转换时并排画面显示实际分析帧；切换原视频可独立播放，不将最后一次识别姿态当作整段同步播放。

转换范围使用双端区间条，拖动起点/终点时定位原视频；仍支持数值输入与键盘调整。返回编辑位于顶部。识别预览每 0.5 秒保留一个抽样以及末帧，超过 120 帧时稀疏化旧样本，按时间回看；不保留大体积原始预测供预览。空预测明确显示未识别提示，不沿用旧姿态。远处空间点使用固定像素大小，避免因距离过远无法看见。

识别结束后单列“整理识别结果”逐帧进度，随后显示“生成场景”“生成工程”。中间数组仅保存适配器实际读取的字段：人物与摄影机保留全部采样帧，场景深度/置信度/遮罩仅保存原适配器原本每秒取用的帧。临时 NPZ 不再压缩，不写未被使用的 RGB、其他密集预测；不改变推理或场景采样规则。

2026-11-06 同源 16.7 秒、12 fps、201 帧、环境网格的实测：旧任务总耗时 312.020 秒，末预览到任务完成 118.587 秒；新任务总耗时 192.092 秒，末预览到任务完成 12.375 秒，其中结果整理 8.141 秒。两次 `scene.json` 逐字节一致，均为 9 个对象；完整桌面流程覆盖 MCP 回看、转换不修改原工程、保存取消、打开内嵌资源工程。总耗时受加载与机器状态影响，不作为固定速度承诺。

模型准备和存储管理移至“设置 → 保存与软件 → 视频反推 → 模型与存储”，转换栏齿轮也可打开。首次准备保留许可确认。新工作区验证包括原视频播放/定位、无模型时选片、预览切换、编辑快捷键隔离、返回编辑保留原画布和参数、1000×720/1600×1000 布局、设置入口与真实识别结果。

## 还原内容与结果文件

还原内容可选“仅人物”或“人物＋场景”。共用 `scene:none|planes|mesh`，不增加独立工程格式；省略仍为 planes。none 保留全部人物与摄影机采样，仅保留首帧深度供原有地面定位计算，避免切换模式改变坐标；不写出环境模型或预览点云。planes 只保存首帧密集数据，mesh 保留每秒场景采样。模型推理保持不变，不将此选项宣传为跳过深度推理。

独立打开只需 reconstructed.director，资源已内嵌。preview.json、previews.json、previews/ 用于任务回看；analysis.json、scene.json、task.json、run.log 用于任务恢复、结果说明和排错。成功或取消后按现有受管目录规则清理 NPZ、抽帧 JPG 及已内嵌 GLB；模型与运行环境跨任务共用。

2026-11-06 还原内容验证：合成预测分别生成 none/planes/mesh，人物对象、摄影机轨迹和地面偏移完全一致，none 仅产出人物 GLB。真实 Windows 桌面以官方样例的 2 秒 / 6 帧验证 none，生成 3 个人物和 1 台摄影机，无场景模型；转换完成自动移除原始 NPZ、JPG、重复 GLB，工程独立打开成功。覆盖内容选择/返回恢复、参数隐藏、预览不含场景点、MCP 查询与回看、未保存编辑的打开处理。此为流程验收，不是识别质量或新素材泛化验收。

## 人物外形与动作适配

人物属性的“人物外形”下拉框选中后立即应用，支持撤销；失败时恢复实际模型选项。UI、MCP 和离线工具共用 `replace-actor` 操作，目标为内置人形资产。原人物 ID、名称、颜色、变换、走位、显示区间及片段 ID/起止/速度/素材起点保留。原生片段转成 retarget，来源 GLB、完整骨架映射、初始校正姿态、单位及朝向独立保留；不重新分析视频。已有 retarget 片段再次换外形不改来源。骨架坐标和初始姿态适配复用 HumanoidRetarget，简化躯干继续累计来源胸椎运动。原资源仍受引用检查保护。
